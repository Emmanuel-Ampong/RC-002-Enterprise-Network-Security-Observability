# RC-002 M2 — Minimum Observability Topology Verification

## Milestone

**M2 — Minimum Observability Topology**

## Status

**VERIFIED**

## Purpose

M2 establishes the minimum network architecture required for subsequent
security-observability and telemetry experiments in RC-002.

The milestone extends the initial laboratory environment established in M1
into a segmented, routed enterprise-style topology containing user,
server, observability, and external network zones.

M2 focuses on establishing a reproducible network and application baseline.
Telemetry collection, packet analysis, anomaly generation, detection, and
security-event correlation are intentionally deferred to later milestones.

---

## Final Architecture

The implemented topology contains four logical network zones:

| Zone | Network | Primary Components |
|---|---|---|
| USER | 192.168.10.0/24 | CLIENT-1, CLIENT-2, ACCESS-SW1 |
| SERVER | 192.168.20.0/24 | SERVER-1, SERVER-SW1 |
| OBSERVABILITY | 192.168.30.0/24 | TELEMETRY-1, OBS-SW1 |
| WAN / INTERNET | 192.168.42.0/24 | EDGE-R1, GNS3 NAT |

`EDGE-R1`, implemented using FRRouting, provides Layer-3 connectivity
between the internal zones and the external NAT segment.

### EDGE-R1 Addressing

| Interface | Address | Function |
|---|---|---|
| eth0 | 192.168.10.1/24 | USER gateway |
| eth1 | 192.168.20.1/24 | SERVER gateway |
| eth2 | 192.168.30.1/24 | OBSERVABILITY gateway |
| eth3 | DHCP-assigned on 192.168.42.0/24 | WAN / NAT uplink |

During verification, `eth3` received `192.168.42.184/24` from the
GNS3 NAT service with a default route through `192.168.42.1`.

The WAN address is DHCP-assigned and should therefore not be treated as
a permanently fixed laboratory address.

## Application Baseline

A lightweight Lighttpd HTTP service was deployed on SERVER-1.

The service listens on TCP port 80 and serves an RC-002 test page from:

`http://192.168.20.10/`

The application provides reproducible application-layer traffic for
subsequent observability experiments.

Lighttpd was configured to start automatically during the default Alpine
Linux runlevel and remained operational following a SERVER-1 reboot.

## NAT Validation

IPv4 forwarding was verified as enabled on EDGE-R1:

`net.ipv4.ip_forward = 1`

Source NAT was implemented using an iptables MASQUERADE rule on the
WAN-facing `eth3` interface.

During validation, the POSTROUTING MASQUERADE counter increased from:

`14 packets / 2268 bytes`

to:

`15 packets / 2352 bytes`

following externally destined traffic generated by SERVER-1.

SERVER-1 simultaneously demonstrated successful external connectivity
with zero packet loss to `8.8.8.8`.

This provides evidence that internal traffic was successfully forwarded
through EDGE-R1 and source-NATed toward the GNS3 NAT network.

---

## Observations

Several initial routed ICMP tests involving Linux hosts and the VPCS USER
zone exhibited elevated latency on the first few replies before
stabilizing to low-millisecond response times.

Examples included approximately:

- 3006 ms → 2009 ms → 1011 ms → normal latency
- 3007 ms → 1957 ms → 948 ms → normal latency

No packet loss occurred during these tests.

The cause was not established during M2. Therefore, the behavior is
recorded as an observation rather than attributed to a specific network,
emulation, ARP, or host-processing mechanism.

This observation may provide a useful candidate for later telemetry and
packet-level investigation.

## Scope Boundary

M2 establishes the infrastructure required for observability experiments,
but does **not** demonstrate security observability itself.

The following capabilities remain outside the M2 scope:

- centralized log collection;
- Syslog forwarding;
- packet capture and traffic inspection;
- telemetry normalization;
- baseline traffic characterization;
- abnormal traffic generation;
- anomaly detection;
- event correlation;
- automated response.

These capabilities will be introduced and evaluated in subsequent RC-002
milestones.

---

## Milestone Conclusion

M2 successfully established and validated a lightweight segmented network
capable of generating routed internal, application-layer, and
external traffic.

The resulting architecture provides the controlled network foundation
required to begin the OBSERVE phase of Project Aegis.

**M2 Verification Status: PASS**
