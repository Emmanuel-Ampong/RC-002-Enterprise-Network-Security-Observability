\# RC-002 - High-Level Design



\## Enterprise Network Security Observability and Telemetry



\*\*Project:\*\* Project Aegis

\*\*Research Cycle:\*\* RC-002

\*\*Project Aegis Phase:\*\* OBSERVE

\*\*Document Type:\*\* High-Level Design

\*\*Status:\*\* Implemented and retrospectively documented from the verified M1-M4 environment

\## 1. Purpose



This document describes the high-level architecture of the RC-002 Enterprise Network Security Observability and Telemetry laboratory.



RC-002 extends the secure-network foundation established during RC-001 by introducing centralized observability capabilities and an experimental environment for studying measurable network and system behavior.



The architecture is designed to support the RC-002 research question:



> To what extent can centralized network telemetry improve the observability of normal and abnormal behavior within a segmented enterprise network while preserving legitimate network operations?



\---



\## 2. Design Objectives



The RC-002 architecture is designed to:



\- Provide a reproducible GNS3-based experimental environment.

\- Maintain logical separation between user, server, observability, and WAN functions.

\- Preserve legitimate inter-zone and Internet connectivity required by the experiments.

\- Provide centralized collection of selected system telemetry.

\- Preserve source attribution for collected telemetry.

\- Support packet-level observation of selected network interactions.

\- Establish a measurable normal-operation reference condition.

\- Support subsequent controlled abnormal-behavior experiments.

\- Permit comparison of observations between normal and controlled abnormal operating conditions.

\- Preserve legitimate network and infrastructure-service operation while observability mechanisms are active.

\## 4. Architectural Components



\### 4.1 EDGE-R1



EDGE-R1 provides Layer-3 connectivity between the laboratory zones and connectivity toward the GNS3 NAT/Internet environment.



Its architectural responsibilities include:



Inter-zone routing.

Connectivity between USER, SERVER, and OBSERVABILITY zones.

Connectivity toward the WAN/Internet environment.

Generation of infrastructure telemetry used in centralized observation.



\### 4.2 User Zone



The USER zone represents enterprise client systems.



CLIENT-1 and CLIENT-2 provide controlled endpoints from which legitimate and experimental network interactions can be generated.



\### 4.3 Server Zone



The SERVER zone contains SERVER-1.



SERVER-1 provides a reproducible HTTP application service used to validate application connectivity and characterize legitimate application behavior.



SERVER-1 also acts as a telemetry source for centralized system-event collection.



\### 4.4 Observability Zone



The OBSERVABILITY zone contains TELEMETRY-1.



TELEMETRY-1 provides centralized collection and preservation of selected telemetry generated by systems within the experimental environment.



The separation of telemetry infrastructure from user and server systems provides a distinct logical observation function within the laboratory.



\### 4.5 WAN/Internet Zone



The WAN/Internet zone provides external connectivity through the GNS3 NAT environment.



This allows RC-002 to observe both internal network interactions and traffic traversing an external path.



\## 5. Observability Architecture



RC-002 combines multiple forms of evidence rather than relying on a single observable.



The principal observation mechanisms established through M1-M4 include:



Centralized Syslog collection.

Source-attributed system telemetry.

Packet-level traffic capture.

Connectivity measurements.

Application-level observations.

Latency measurements.

Operational verification.



SERVER-1 and EDGE-R1 provide centralized telemetry to TELEMETRY-1.



This architecture allows network interactions and system-generated events to be considered as complementary evidence.



\## 6. Experimental Architecture



RC-002 uses a controlled comparison model:



NORMAL BASELINE -> CONTROLLED CHANGE -> OBSERVATION -> COMPARISON



M4 established the normal reference condition using:



N01 - Inter-zone ICMP.

N02 - HTTP application access.

N03 - Internet-facing ICMP.

N04 - Normal system activity.



The resulting measurements provide the reference condition for subsequent controlled abnormal-behavior experiments.



A difference from the baseline is not, by itself, considered evidence of malicious activity or automated threat detection.



RC-002 evaluates whether selected telemetry makes behavioral differences observable.



\## 7. Design Principles



The architecture follows the following principles:



Segmentation



User, server, observability, and external connectivity functions are logically separated.



Centralized Observation



Selected telemetry is collected centrally to improve visibility across multiple sources.



Source Attribution



Telemetry should retain sufficient source information to associate observations with their originating systems.



Reproducibility



Laboratory configuration, experimental procedures, datasets, results, and verification evidence are retained within the RC-002 repository where appropriate.



Operational Preservation



Observability mechanisms should not materially disrupt the legitimate connectivity and infrastructure services required by the experimental environment.



Evidence-Based Evaluation



Research conclusions should be based on retained measurements and experimental evidence rather than dashboard appearance or subjective visual inspection.



\## 8. Relationship to Project Aegis



Project Aegis progresses through:



BUILD -> HARDEN -> OBSERVE -> DETECT -> INVESTIGATE -> RESPOND -> ADAPT



RC-001 established the BUILD and HARDEN foundation through secure enterprise network architecture, segmentation, routing, management hardening, infrastructure services, and systematic validation.



RC-002 represents the OBSERVE phase.



Its purpose is to establish whether security-relevant behavior can be systematically collected, centralized, measured, and compared before later Project Aegis research considers detection and investigation mechanisms.
